# What goes on the internet

Most WFMT features run entirely on the local computer and read the game's journal files.

The journal is the only data a third-party tool receives about play, and not every event is logged. A few features add data from outside sources: data reported by the community (Spansh, EDSM, Canonn, edastro, Raven Colonial) and figures that Frontier's servers provide to a signed-in EDMC.

This page lists every feature that contacts an outside site. See [How WFMT knows what it knows](README.md#how-wfmt-knows-what-it-knows).

**Summary:** most lookups run only on a button press or after being enabled on the **Online** tab of Settings. The exceptions:

- **BGS tick detection (every minute)** is on by default (turn it off on the **Online** tab, or with **Turn all off**).
- The **Rare Goods Finder** and the **Codex "Not found" tab** have no on/off setting and contact their service when opened.

**Switches:** Settings → WFMT → Online is the one set of controls for every lookup that contacts another service. It has a checkbox for each of the 21 lookups, grouped under the service they contact (Spansh, EDSM, Raven Colonial, Community tick service, GitHub).

- **Turn all off** unticks every lookup, automatic updates and BGS tick detection included. **Reset to defaults** puts every box back as WFMT ships it (only BGS tick detection is on). Both only set the boxes; **OK** or **Apply** in EDMC's Settings saves them like any other setting.
- The page also lists the lookups that run only when you press or open something (they have no switch), and holds the **Local star index** controls (**Download and build**, **Update**; see the second row of the table below).
- The place where each switch used to be (Trade, Mining, BGS, Colonization, Exploration, the Overlays tabs, Window and Updates) now shows a one-line note saying the lookup is switched in Settings → WFMT → Online.
- A feature that cannot work without a lookup says so where it is used, only while the lookup is off: `This needs "<lookup name>" (<service>), which is off. Turn it on in Settings > Online.` Nothing is shown while the lookup is on. The extras that only improve a feature (the Exploration Value extras, the Boxel Survey and Region Sweep EDSM options, the overlay lookups, system-name suggestions, automatic updates) show no warning.

### Trade lookup request counts

Trade lookups run only on a button press:

- **Find routes**: sends one request, then checks for the answer every 5 seconds, for up to 4 minutes, until
  **Cancel** is pressed.
- **Near me** / **Galaxy**: two requests each (stations, then fleet carriers). One if carriers are hidden.
- **Best picks**: about four requests (five with carriers), one after another. **Find sources** in Mission mode: the same, per commodity, one commodity at a time.
- **Round trip**: one to three requests of up to 100 stations each.

## What never goes online

Everything else makes **no internet connection at all**:

- Powerplay tracking, Missions tracking, Inventory and Screenshots. The exceptions are the Powerplay Sessions window's Post to Discord button and the Missions **Find sources** button, both listed above.
- Copy diagnostics (clipboard only).
- **Find where to buy** on an engineer's items opens the same Spansh lookup as Source commodities (it needs **Trade: routes, prices and best picks** on and a press of **Find sources**), and **Look up the nearest Thargoid site** downloads Canonn's list of Thargoid sites the first time it is used (the same Google-hosted list as POI Reference: Canonn, in the table above). Neither sends anything but what those entries above describe.
- The separate diagnostic log (a file on the local computer in EDMC's `logs/WFMT` folder, off by default; nothing is sent anywhere, and the commander name, home folder and webhook links are hidden in it).
- The Missions overlay card and window (with pinned missions).
- The Ship planner. It reads a pasted loadout or import link, and the commander's journal for the ship flown. Its **Open in Coriolis** and **Open in EDSY** buttons only open the browser at that site when pressed, with the loadout in the address.
- The Upgrade planner (the commander's journal for the gear owned).
- Colonization tracking, history and the shopping list overlay. The parts that go online are the ones listed above (Raven Colonial and Where to buy).
- Organic Scanning, Ship Builds, the Combat Record, Landing Assist and Interdiction Warning.
- Mining History, the mining alerts, and both Mining Books (the Space Mining Book and the Surface Mining Book read the journals). The only mining requests are the opt-in lookups in the Mining row above, such as Get body info.
- Trade's session profit, stock, carrier cargo and History, and the Watch list's prices from the markets opened.

The **overlays** send nothing outside the local computer either:

- WFMT's built-in overlay (Windows) is a window drawn on the local screen.
- With EDMCModernOverlay, WFMT talks to it over a local connection on the local computer (`127.0.0.1`).
- Fonts are files on the local disk: WFMT downloads none, and the font section only copies a selected file.
- Converted screenshots with the overlay drawn on them stay on the local disk.

The overlay features that go online are the opt-in lookups listed above: System targets (EDSM and Spansh), the Powerplay card's look-ahead (Spansh) and the Route overlay's marks (EDSM).

## How WFMT keeps its traffic low

WFMT limits requests to these services:

- Lookups are started or enabled by the user, except BGS tick detection and the two windows named in the summary above.
- Answers are remembered, so a repeated lookup does not send a second request.
- Every request identifies WFMT.
- Requests to Spansh are spaced out, never more than two at once, retried with growing waits when Spansh is busy, and paused for five minutes after repeated failures.
- The page [How WFMT uses Spansh](../SPANSH_USAGE.md) lists every Spansh request WFMT makes, what starts it and how many it sends.

The technical details are in [TECHNICAL.md](../TECHNICAL.md#keeping-api-traffic-low).
